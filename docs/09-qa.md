# QA - Fase 8: Pruebas Funcionales, Móviles y de Rendimiento

## Objetivo
Ejecutar QA integral (funcional, móvil, rendimiento) y cerrar incidencias críticas antes del go-live.

## Alcance de Pruebas

### 1. QA Funcional (Desktop)

#### 1.1 Página de Inicio (Home)
- [ ] Banner principal carga correctamente
- [ ] Enlaces del menú de navegación funcionan
- [ ] Productos destacados se muestran correctamente
- [ ] Llamados a la acción (CTAs) redirigen correctamente
- [ ] Buscador funciona con resultados relevantes
- [ ] Footer con enlaces institucionales funcionan

#### 1.2 Catálogo y PLP (Product Listing Page)
- [ ] Lista de productos carga completamente
- [ ] Filtros por categoría funcionan
- [ ] Filtros por marca funcionan
- [ ] Filtros por rango de precio funcionan
- [ ] Ordenamiento (precio, nombre, nuevo) funciona
- [ ] Paginación funciona correctamente
- [ ] Imágenes de productos cargan
- [ ] Click en producto lleva a PDP correcta

#### 1.3 PDP (Product Detail Page)
- [ ] Información del producto completa (nombre, precio, descripción)
- [ ] Imágenes del producto cargan y zoom funciona
- [ ] Selector de cantidad funciona
- [ ] Botón "Agregar al carrito" funciona
- [ ] Disponibilidad de stock se muestra
- [ ] Productos relacionados se muestran
- [ ] Especificaciones técnicas visibles

#### 1.4 Carrito de Compras
- [ ] Productos agregados aparecen en carrito
- [ ] Cantidad puede modificarse
- [ ] Productos pueden eliminarse
- [ ] Subtotal calcula correctamente
- [ ] Botón "Proceder al checkout" funciona
- [ ] Carrito persiste entre sesiones

#### 1.5 Checkout y Pagos
- [ ] Formulario de datos personales valida correctamente
- [ ] Dirección de envío puede ingresarse
- [ ] Métodos de envío disponibles
- [ ] Cálculo de costos de envío correcto
- [ ] Métodos de pago disponibles
- [ ] Resumen de orden correcto
- [ ] Confirmación de orden funciona
- [ ] Email de confirmación se envía

#### 1.6 Páginas Institucionales
- [ ] Página "Nosotros" carga correctamente
- [ ] Página "Contacto" con formulario funcional
- [ ] Página "FAQs" con contenido completo
- [ ] Políticas de privacidad disponibles
- [ ] Términos y condiciones disponibles
- [ ] Política de envíos disponible

#### 1.7 Búsqueda y Navegación
- [ ] Búsqueda por palabra clave funciona
- [ ] Sugerencias de búsqueda aparecen
- [ ] Resultados de búsqueda relevantes
- [ ] Navegación por categorías funciona
- [ ] Breadcrumbs correctos en todas las páginas
- [ ] Botón "Volver" funciona correctamente

### 3. QA de Rendimiento

#### 3.1 Tiempos de Carga
- [ ] Home carga en < 3 segundos
- [ ] PLP carga en < 3 segundos
- [ ] PDP carga en < 2 segundos
- [ ] Búsqueda responde en < 1 segundo
- [ ] Carrito actualiza en < 1 segundo

#### 3.2 Optimización de Recursos
- [ ] Imágenes optimizadas (WebP, compresión)
- [ ] CSS/JS minificados
- [ ] Caché de navegador configurado
- [ ] CDN para recursos estáticos (si aplica)

#### 3.3 Métricas Core Web Vitals
- [ ] LCP (Largest Contentful Paint) < 2.5s
- [ ] FID (First Input Delay) < 100ms

#### 3.4 Pruebas de Carga
- [ ] Sitio soporta 50 usuarios concurrentes
- [ ] Checkout funciona bajo carga
- [ ] Base de datos responde adecuadamente
- [ ] No hay errores 500 bajo uso normal

```
Fecha detección: [fecha]
Fecha resolución: [fecha]
```

### Criterios de Severidad

**Crítica**: Bloquea funcionalidad core, impide compra, pérdida de datos, vulnerabilidad de seguridad
**Alta**: Funcionalidad importante afectada, workaround difícil, afecta UX significativamente
**Media**: Funcionalidad menor afectada, workaround disponible, problema estético notable
**Baja**: Problema cosmético menor, no afecta funcionalidad

## Proceso de Ejecución

### Fase 1: Preparación (Antes de iniciar pruebas)
1. Revisar documentación de requisitos (Fases 1-7)
2. Preparar ambiente de pruebas (staging)
3. Configurar herramientas de prueba
4. Definir datos de prueba (productos, usuarios, etc.)
5. Establecer criterios de aceptación

### Fase 2: Ejecución de Pruebas
1. Ejecutar QA funcional desktop (1-2 días)
2. Ejecutar QA móvil/tablet (1 día)
3. Ejecutar QA de rendimiento (medio día)
4. Ejecutar QA de SEO (medio día)
5. Ejecutar QA de seguridad (medio día)
6. Ejecutar QA de accesibilidad (medio día)
7. Ejecutar QA de compatibilidad (medio día)

### Fase 3: Registro y Priorización
1. Documentar todas las incidencias encontradas
2. Clasificar por severidad
3. Priorizar incidencias críticas y altas
4. Asignar responsables
5. Establecer deadlines

### Fase 4: Corrección y Re-test
1. Equipo de desarrollo corrige incidencias
2. QA re-testea cada fix
3. Verificar que no se crearon regresiones
4. Actualizar estado de incidencias

### Fase 5: Reporte Final y Sign-off
1. Compilar reporte de QA
2. Documentar incidencias pendientes (si las hay)
3. Obtener aprobación de stakeholders
4. Generar acta de QA firmada

## Entregables

1. **Checklist de QA completado** - Este documento con todos los items verificados
2. **Registro de incidencias** - Documento o spreadsheet con todas las incidencias
3. **Reporte de rendimiento** - Screenshots de PageSpeed, GTmetrix, Lighthouse
4. **Reporte de compatibilidad** - Matriz de navegadores/dispositivos testeados
5. **Acta de QA** - Documento formal con aprobación de QA para go-live
6. **Videos/Screenshots** - Evidencia de pruebas realizadas

## Criterios de Aceptación para Go-Live

### Obligatorios (No Negociables)
- ✅ Cero incidencias críticas abiertas
- ✅ Checkout completo funciona sin errores
- ✅ Pagos procesan correctamente
- ✅ Home y PLP cargan en < 3 segundos
- ✅ Sitio responsive en móvil y tablet
- ✅ No vulnerabilidades de seguridad conocidas
- ✅ HTTPS habilitado y funcional

### Recomendados (Pueden postergarse con plan)
- ⚠️ Todas las incidencias altas resueltas (o plan de fix post-launch)
- ⚠️ Core Web Vitals en rango "Good"
- ⚠️ Accesibilidad WCAG 2.1 AA
- ⚠️ Compatibilidad con todos los navegadores listados
